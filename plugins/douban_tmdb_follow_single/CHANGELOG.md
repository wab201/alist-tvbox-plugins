## v64 测试版 - 2026-08-13

- History 追更匹配按季集优先，较新的低集数记录不会覆盖较旧但已播放到更高集数的记录。
- 双向同步分开保存完整云端快照和本机导入差异；导入差异为空时仍会回写追更进度。
- 轻量 History 刷新完成后立即合并追更状态，并对发生变化的条目启动定向线路预热。
- 追更预热缓存加入目标集版本，旧的 E04 缓存不能阻止 E05 重新搜索、验活和绑定。
- 就绪线路必须覆盖当前目标集；已绑定的 E05 线路不会被旧 E04 刷新结果覆盖。
- FongMi 页面反射刷新失败时回退到 loopback 分类刷新，减少必须退出重进才能看到状态的情况。
- 播放成功后分阶段刷新 FongMi 最近观看，覆盖 History 异步落库和 5 秒保存节流；新播放会使旧云端快照失效，防止旧请求回写高集数进度。
- 完整线路就绪和自动绑定只接受单一播放组连续覆盖目标集，跨组残缺资源不再被误报为完整线路。

## v57 - 2026-08-12

- 自动化回归增至 204 项，并继续通过双运行时、ATVP 直播放、FongMi 分类参数和 AList-TVBox 1.44.0 合同门禁。

- 兼容 PanSou 原始 `data.merged_by_type` 和 `data.results[].links[]` 返回，补齐独立密码字段、115/移动补充域名、结构化盘型别名以及 `magnet/ed2k` 识别。
- 相同分享 URL 跨结果和跨 API 规范化合并，依次保留标题匹配、链接级 `work_title`、完整提取码和较新 RFC3339/数值时间记录；不同 API 的同名不透明 ID 保持独立播放列表。
- 前台候选、已验证缓存和盘搜/电报后台验活均先从每个已命中的 API 保留一条，再用剩余名额补入同源备选，避免单个来源占满前八次详情尝试或后台验证预算。
- 统一识别 `pwd/password/passcode/pass_code/share_pwd`、中文提取码和短片段密码；裸 `#A1` 与查询参数密码共享同一分享身份，磁力按 BTIH、ED2K 按内容哈希去重。
- 四 API 的标题、备注、来源和线路元数据统一限长；PanSou 在保留有限重复修正窗口的同时限制链接扫描总量，长磁力/ED2K 继续使用独立输入上限。
- PanSou 的 `results[].links[]` 与各 `merged_by_type` 网盘来源改为轮询扫描，单个大来源不能独占预算；显式 `work_title` 作为权威标题，冲突时不会被父级标题误救回。
- 四 API 通用行改为字段白名单，丢弃未知嵌套大字段；空值或超长 URL 密码不会阻止独立提取码补入，Base32 与 40 位十六进制 BTIH 统一到同一资源身份。
- 详情前台和后台共用最多 4 个资源搜索工作线程，并把四类 API 的第二候选纳入 8 次详情验证范围；能力缓存冷加载不会覆盖并发实时探测结果。
- 播放组和分集解析全面改为有界扫描；合并逻辑先从四类 API 各保留最佳线路，再对剩余候选按质量排序并应用线路、分集和输出字节预算。
- AT 已返回 `parse=0` 且通过安全 URL 校验、但桌面 Range 探测未知时不再丢弃线路；客户端播放阶段继续尝试，并且不会把未知结果缓存为 `reachable=true`。
- History 导入在写入本机前重新读取本机记录，避免双向同步把较新的本地集数或进度覆盖为云端旧快照。
- 私网 AList-TVBox 地址支持有无显式端口的 `http`/`https` 双向候选回退；当前订阅地址优先于旧地址，公网 HTTPS 不降级到 HTTP，POST 仅在明确的连接建立或 TLS 协议不匹配错误时重试，History 错误正文按流式字节上限读取。
- 资源 API 能力结果绑定当前后端身份和初始化代次，旧后台请求不能把新后端误标记为接口缺失或可用。

## v53 - 2026-08-11

- 修正同版本仓库导入不会重新拉取源码的问题，后续每次源码变更都会递增插件版本，确保 AList-TVBox 能识别并刷新更新。

- History 输入、记录和线路身份增加边界保护，冷启动或旧缓存异常时不会把未知状态写回云端。

- 追更播放成功后长期保存可刷新的资源和播放线路标识；不保存签名直链、完整播放响应或临时鉴权参数。
- 详情页优先验活上次成功线路，线路有效时即使 History 尚未同步也会继承绑定集数并置于第一组；失效后在后台替换为可用线路并保留观看进度。
- 详情页最多显示一条主线路和两条独立备选线路，备选标记网盘或盘搜来源，按清晰度优先排序且不进入共享分线路点播。

- 追更确认、追更管理和追更动态在进入时检查待同步播放记录，使已追更集数及时保持一致。
- 追更管理新增当前客户端的 History 分享开关，可分别禁止本机追更播放记录或普通观看记录继续上传；云端拉取、合并、本机导入和其他允许类别的上传保持运行。
- 分享开关仅保存在当前客户端，不保存设备指纹；关闭后只影响未来上传，不删除已存在的云端 History，默认保持两类均允许。
- 客户端缓存暂时无法读取时先暂停本机 History 上传，避免冷启动恢复旧记录共享；云端拉取和本机导入继续运行。
- History 读取和上传增加总量、记录数、单条记录及字段长度保护，异常数据不会拖慢播放详情或同步链路。
- 旧缓存中的直链、危险 URI 和失效线路标识会在读取时清理；自动网络重试仅用于只读请求，写入和鉴权重试保持显式控制。
