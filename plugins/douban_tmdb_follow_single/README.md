# 豆瓣 TMDB 追更助手

- 插件 ID：`douban_tmdb_follow_single`
- 当前版本：`60`（公开测试版）
- 运行环境：AList-TVBox raw Python 插件；兼容空 EXT 直接 FongMi 元数据模式
- 最低兼容基线：AList-TVBox `1.42.0`
- 当前验证环境：AList-TVBox `1.44.0`
- 发布状态：测试版索引已启用，可通过仓库导入；稳定回退基线为 v57

## 主要能力

- 浏览豆瓣和 TMDB 的电影、剧集与季集信息。
- 建立追更列表，显示追更动态并管理已看、取消和同步操作。
- “追更确认”直接读取 FongMi 收藏和播放记录作为待选，确认后才加入追更；收藏和播放记录不会自动改写追更标记。
- 所有电影、剧集导航卡直接打开 FongMi 全局搜索，导航页不再提供追更/浏览模式切换。
- 云端 History 在后台自动同步，日常首页不再显示独立“云端历史”分类。
- 手动同步和通讯检测集中在“追更管理”，空追更列表时同样可用。
- 无完整写入账号时严格保持只读；上传、导入或进度回写单项失败不会中断其余可执行步骤。
- 操作结果以页面状态卡持续显示，不依赖 Toast 作为唯一反馈。
- 首次追更没有播放记录时，也能请求 AList-TVBox 搜索真实资源。
- 使用标题、别名、年份和季号进行保守匹配；单季剧不把季号作为硬性门禁。
- 自动发现后端已提供的资源搜索模式，隐藏明确缺失的模式。
- `vod1`、`vod`、`pansou`、`telegram` 四类 API 统一读取多种标题字段并去除年份、季集、画质、网盘和 HiveWeb 等装饰；兼容 PanSou 原始 `merged_by_type/results.links`、顶层及嵌套权威 `work_title`、链接备注和独立密码字段，多来源按轮询预算扫描，链接资源先于通用父记录占用结果名额。
- 相同分享 URL 跨 API 规范化合并，优先保留标题匹配、链接级 `work_title`、完整提取码和实际时间更新的记录；不同 API 的同名不透明 ID 不会互相覆盖，115、移动、123、阿里等盘型别名和补充域名可准确识别。
- 插件初始化、首页和追更分类会限量后台预热最多 3 个追更条目的可播放列表；热缓存命中时首次详情不再重新搜索或验活全部候选，后台新增线路会定向刷新当前详情页。
- AT 已返回安全 `parse=0` 直链但桌面 Range 探测未知时，详情保留线路并交给客户端尝试，不把“未探测”误记为已实测可达。
- AList-TVBox 各网盘播放响应中的标准 `Cookie`、`Referer`、`Origin`、`User-Agent`、`Accept`、`Range` 和 `Content-Type` 会随最终直链交给播放器；夸克 CDN 因缺少 Cookie 返回 `412`/`bad http status` 是已确认案例，未批准的认证头仍会丢弃。
- 按首开时间、稳定性、编码兼容性、分辨率和字幕情况在后台评估线路，不在详情页显示内部评分。
- 剧集默认线路先比较已验证真实续播、截至 TMDB 最新集的完整覆盖、是否包含最新集及明确集数，再比较绑定和画质；完整线路不会被单集高画质候选压到后面。
- 同一网盘的多个残缺分享会按季集合并缺失集，补入集数名称追加“补全”标识；这里以详情中含合法分集播放 ID 作为可播放分享依据，后台线路探测只负责排序和状态展示；无法明确网盘类型时不跨线路拼接。
- provider 会从四类 API 候选、预热缓存、播放参数和成功线路一直保存到追更绑定，重启后仍能识别同盘；未知、非规范或互相冲突的 provider 始终按失败关闭处理。
- 详情页优先使用已验证热缓存；热缓存未命中或仍在预热时使用上次成功绑定线路兜底，最多保留 5 条独立有效线路。四类 API 先各保留最佳一组，再从全部剩余候选按完整度和清晰度补入名额，最后才应用分集和输出预算，避免单一来源遮蔽其他播放列表。
- 前台四 API 搜索与盘搜/电报后台补全使用独立有界线程池；重写阶段最多保留 64 个候选组，低质量大分集组不会在全局质量选择前遮蔽后续高质量线路。
- 播放 ID 在验活和网络入口统一限长；已验证详情缓存只保留播放字段与有限显示元数据，并使用 64 条 LRU 上限。
- 播放成功会保存可刷新的资源、线路和季集标识，不保存签名直链或完整播放响应；原绑定失效后在后台替换线路并保留观看进度。
- 保存追更状态时会再次统一清洗资源绑定；只保留不透明资源 ID 或可识别网盘域名的分享链接，签名媒体直链、磁力和其他 URI 不进入长期状态。
- 播放请求、质量记录、线路缓存和后台预热任务都绑定启动时的容器后端代次；切换地址或令牌后，旧请求不能写入新后端状态。
- 播放超过 8 分钟后进入待同步状态；收到退出回调时立即触发 History 同步，没有回调时约 5 秒检测一次；追更确认、管理和动态页面会刷新待同步结果。
- 使用 AList-TVBox History 匹配选集和续播位置。
- 私网 History 可在 HTTP/HTTPS 间适配明确的连接或 TLS 协议不匹配，支持 IPv4/IPv6 回环和 IPv6 ULA，当前订阅地址优先于旧地址；公网主机不降级，发送状态不明的 POST 错误不会跨协议重试，异常正文始终按流式字节上限读取。
- 异地客户端进度依赖 AList-TVBox 云端 History；未配置可写的 `USER`/`ADMIN` 账号时只读取已有云端记录，不会上传本机新增播放进度。
- “追更管理”可在当前客户端分别控制追更播放记录和普通观看记录是否继续上传到云端；该设置不阻断云端拉取、合并、本机导入或其他允许类别的上传。
- 客户端分享设置保存在本机缓存，不建立或上传设备指纹；关闭只影响未来上传，不会删除已在云端的记录，默认两类均允许。
- 本机分享设置暂时读取失败时会暂停上传，待设置成功读取或用户重新保存后恢复；云端拉取、合并和本机导入不受影响。
- 同一源码可选作为 AList-TVBox 详情/播放过滤器复用。
- 空 EXT 直接作为 FongMi `.py` 站点时保留分类、搜索、元数据详情和标准直链播放器返回；追更、History 与网盘资源仍以 AList-TVBox raw 插件订阅为完整运行模式。

## 必要配置

使用完整功能时只需在插件 EXT 中保留：

```json
{
  "atvp_plugin_mode": "alist-tvbox-raw",
  "tmdb_access_token": "YOUR_TMDB_READ_ACCESS_TOKEN"
}
```

`tmdb_access_token` 从 TMDB 网站的 **设置 -> API -> API Read Access Token** 获取。需要把本机播放记录写回 AList-TVBox History 并同步到其他客户端时，再填写可登录当前容器的 `USER` 或 `ADMIN` 用户名和密码；用户名或密码任一留空都会按只读模式运行，只读取已有云端 History，不会把本机新增进度上传到其他客户端。

推荐直接使用带中文说明的 [extend.example.json](extend.example.json)。不要手工添加 AList-TVBox 生成的 `api`、`token`、`secret`、`loader`、`source` 或 `raw` 外层字段。
