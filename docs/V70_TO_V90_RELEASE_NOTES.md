## V70 基线

V70 提供豆瓣/TMDB 浏览、追更管理、AList-TVBox 资源搜索、线路预热、History 同步和 FongMi 双运行时兼容。V90 保留这些能力，但替换了 V70 的开发结构、同步协议适配、身份模型、候选来源、缓存和可靠性边界。

V71-V79 没有形成独立公开版本；后续开发从 V80 的独立重构线继续。

## V80：架构、可靠性和安全基线

- 建立“开发态模块化、发布态单文件”合同，拆分资源模型、Provider、Schema、归一化、匹配、评分、合并、排序和输出准入。
- 对接 AList-TVBox `1.45.x` 以后 `/api/playback/*` 通道，支持增量游标、完整快照、墓碑、导入提交、UID 重识别和旧接口受控回退。
- 固定唯一传输重试所有者、绝对超时预算、生命周期取消、Provider 熔断/并发隔离/健康状态和 History 持久事件队列。
- 统一 JSON/HTML 响应大小、结构和字段边界，逐跳验证媒体重定向，限制跨域请求头并集中脱敏诊断。
- 增加缓存 stale/backoff、后台任务舱壁、诊断事件/快照和搜索、播放、History 并发所有权。
- 上游源码合同最终推进到 AList-TVBox `1.51.1 / 47432df300c1ee54e799fe9c7a3eb169823c2f0e`。

## V81：播放记录与追更状态

- 播放状态升级为 v2，保留完成状态、导航坐标、网盘身份和远端更新时间。
- 强身份冲突不再依靠标题覆盖，显示“播放记录待确认”。
- 已看水位单调前进，重看低集仍可更新当前续播；迟到墓碑不删除更新状态。
- 追更动态改为全局排序后分页，并统一简体中文进度和操作文案。

## V82：快速同步与追更交互

- 使用 AList-TVBox 播放进度通道进行快速增量同步，避免每次执行完整 History 合并。
- “检查同步连接”等操作提供持续状态反馈，不再只依赖短暂提示。
- 加入 AList 风格资源名清洗、候选标题放宽和《沧元图》等剧集匹配修复。
- 播放成功线路进入可恢复绑定，收敛重复选集占位和无效提示。

## V83：线路预热持久化与过滤器 owner

- 后台线路预热在 Range 验证成功后立即写入安全长期绑定；失效后再刷新。
- 绑定只保存资源 ID、播放句柄、季集、Provider 和质量摘要，不持久化签名 URL、Cookie 或 Token。
- 资源标题规范化和过滤器代码形成独立 owner，并验证与生成单文件中的方法语义一致。

## V84：恢复多模块构建

- 停止直接扩改单文件，将追更交互、候选识别、播放记录合并、线路预热与恢复、播放列表输出、版本元数据恢复为六个明确 owner。
- canonical、private staging 和公共单文件均为构建产物，不作为开发输入。
- 发布谱系固定 V80-V90 的来源指纹，历史包只读，后续按 owner 和依赖变化做局部验证。

## V85-V86：交互与全量主动预热

- 修复追更确认失败后的重复刷新和无限尝试，失败状态有界并可清除。
- 取消追更并入“追更管理”的下级操作，不再占用独立分页。
- 主动预热入口和进度卡在追更管理中可见，以有界并发处理全部追更条目。
- 预热成功条目显示可直接播放状态；已验证线路写入长期绑定，打开详情优先复用。
- 强化图片、分类、详情和播放线路的客户端缓存；全局交互统一为简体中文。
- 多集电视剧、综艺、真人秀可追更；电影、独立视频和已知 0/1 集项目拒绝。

## V87：扩展候选插件源

- 当 `/vod`、`/vod1`、PanSou 和 Telegram 候选不足或不覆盖目标集时，可从当前活动订阅的受控插件白名单补充候选。
- 补充候选仍必须通过标题评分、详情转换、播放器返回、安全输出、Range 和目标集覆盖验证。
- 单一插件失败被隔离，不阻断其他来源；原始插件播放 ID、分享 URL 和签名 URL 不进入长期状态。

## V88：服务端 TMDB 回退与安全缓存

- 客户端 TMDB 传输失败时，可通过 AList-TVBox `/api/tmdb/meta` 通道回退。
- 成功结果进入现有安全缓存，重复确认不再重复请求或形成无限重试。
- 继续保留电影冲突检查和单集项目排除边界。

## V89：临时剧集身份

- TMDB 尚未收录的新剧可使用 `local:tv:<标题规范化哈希>` 临时身份；有豆瓣 ID 时保留 `douban:<subject_id>` 来源别名。
- 临时身份保存标题、别名、年份、电视剧类型、集数/连载证据、当前进度和线路绑定。
- TMDB 后续收录后迁移为 `tmdb:tv:<id>`，合并身份和线路，不丢失较新的本地播放进度。
- TMDB 空数据或空进度不能覆盖已有有效身份和本地进度。

## V90：选择性 TMDB 双链路热备

- 冷查询先启动客户端 TMDB；超过 `800ms` 未完成，或客户端返回空结果、降级、传输失败时，再启动 AList-TVBox 服务端通道。
- 显式多集证据可采用最先返回的高可信电视剧；类型不明确时仍等待客户端电影冲突检查。
- 两条通道分别保留最近 `8` 次健康样本；连续失败 `3` 次后短期降级 `60s`。
- 任一可信结果写入既有身份缓存，不固定双发，不增加应用层无限重试或通用缓存框架。
